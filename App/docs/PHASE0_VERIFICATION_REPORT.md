## 5) خطأ حرج اكتُشف وأُصلح أثناء الفحص (غير موثق سابقًا)

**العنصر:** `POST /api/v1/payments/webhook` — معالجة أحداث Stripe.
**السبب الجذري:** `stripe.Webhook.construct_event()` في Stripe ≥ v15 يُرجع `StripeObject` وليس `dict`؛ الكود كان يستدعي `event.get("type")` فكان يفشل بـ `AttributeError: get` على كل حدث موقّع صحيحًا (خطأ 500 بدل المعالجة).
**الإصلاح:** `routers/payments.py` — بعد `construct_event`, تحويل النتيجة عبر `to_dict()` إذا كان متاحًا.
**التحقق:** بعد الإصلاح، توقيع صحيح = 200 + منح صلاحية؛ توقيع خاطئ = 400.

## 6) المخاطر/الملاحظات المفتوحة المتبقية

1. **متغيرات OIDC** (`OIDC_ISSUER_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`): غير موجودة في ملف البيئة المقدم — تُحقن من المنصة عند النشر. التدفق الكامل للدخول لا يمكن إثباته محليًا بدونها. **المطلوب:** إعادة اختبار تدفق تسجيل الدخول بعد النشر/الحقن.
2. **`STRIPE_WEBHOOK_SECRET`:** المستخدم هو مفتاح `whsec_...` اختباري (اختبار). قبل الإطلاق الفعلي يجب استبداله بمفتاح live + توجيه Stripe إلى `/api/v1/payments/webhook`.
3. **السيلفي في localStorage** (`AnalyzePage` + `tutorialCache`): مؤجل بقرار CTO. يُنصح بتحويله إلى `Blob`/`ObjectURL` داخل الجلسة في المرحلة 1.
4. **`vercel.json`** ما زال يشير إلى `beauty-fit-ai-progect.onrender.com` (خطأ إملائي قديم) — يُصحح قبل الإطلاق.
5. **اختبار Playwright** أُضيف (`frontend/e2e/app.spec.ts` + `playwright.config.ts`) — نقطة بداية جيدة لأتمتة المرحلة 1.
6. **جرى منح صلاحيات اختبارية** في قاعدة البيانات (`test-user-001`, `test-webhook-user2/3`, `final-check-user`) — تُحذف قبل الإطلاق.
